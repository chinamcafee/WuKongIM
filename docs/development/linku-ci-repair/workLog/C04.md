# C04：迟到 ACK 归属测试的调度预算

2026-10-05。首个修复 CI 的三节点任务已通过；Ubuntu internal unit 暴露了额外的测试调度问题，证据见 evidence/ci-second-failure.txt。

## 原因与范围

TestClientTimedOutAttemptLateAckCannotStealRetry 的 5ms AckTimeout 同时约束故意超时的首次发送和需要成功的重试。Fake server 一直等收到 retry 才发 first ACK，因此首次超时由因果顺序保证；重试成功不应隐含真实 TCP + goroutine 调度须在 5ms 内完成。CI 失败的是 retry AckTimeout，不是旧 ACK 归属错误。

仅将该测试用例的显式 AckTimeout 设为 200ms，并注明用途。生产 Client、默认超时、业务发送/幂等/ACK 归属代码和 CI workflow 超时均未改。Fake server 行为不变；首次必须返回 ErrAckTimeout、retry 使用新 ClientSeq、稳定 ClientMsgNo，以及 MessageID 必须是 912 的断言全部保留。错误把 first ACK 911 归属给 retry 仍会失败。
