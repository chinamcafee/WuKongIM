## 真实源诊断

主机 `175.27.245.108`，源 `/root/wukongim_v2_bak` 的节点 1001、1002、1003 均保持停机；现有目标部署位于 `/root/wukongim`。本轮只使用隔离演练目录，未操作现有 v3 数据或服务。

1. `empty-channel-09` 曾临时允许空身份进行全量预检，262.276 秒后在源索引检查报 `migration spool batch key conflict`。观察到的峰值 RSS 224,817,152 字节，最低剩余空间 11,534,733,312 字节。没有 PREPARED 成功，也没有创建目标输出。该尝试使用的存储兼容方案已撤回，其结果仅作为历史诊断证据。
2. `index-collision-10/11` 因诊断器自身的 50 万项上限退出；不作为数据库损坏结论。
3. `index-collision-12` 用 8,192 项窗口扫描，21.976 秒完成。三个节点分别扫描 1,031,141 / 1,035,215 / 1,035,221 个预期索引项，窗口内观察到 64 / 58 / 61 次冲突。这不是全库去重总数，也不是权威副本选择证明。
4. `duplicate-detail-13` 定点读取，8.437 秒完成。三个副本均存在同一频道的 seq **1093 / 1094**，共享 message_id **1861220579151880192**，除 MessageSeq 外已存字段相同，原 message-ID 索引指向 1094。两条正文 SHA-256 均为 `6a09506e4e85a673c063c8b51e053370c3ba1f020c3f935c0e053be7d028fbea`。
5. 同时核对的一对会话记录，仅 CreatedAt / UpdatedAt 不同，原频道索引指向较大物理 ID。不同原版读取接口的去重规则不能自动视作同一业务语义；尚未批准合并或舍弃。

上述远程执行记录均确认 601 个源文件的大小/mtime/inode/mode 未变化，三个现有 v3 容器仍健康。诊断只输出必要数值、字段差异和摘要，不打印原账号、凭据或正文。

不兼容消息仍须保留，但现有 v3 要求 message_id 唯一，因此不能同时承诺“两个序号共用原 ID 全部导入”与“保持现有唯一性”。当前保持失败状态，不代替用户决定修改或丢弃哪条记录。空身份、插件运行/配置映射也尚未解决。
