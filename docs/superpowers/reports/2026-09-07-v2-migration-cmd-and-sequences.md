## 已实现行为

迁移计划增加显式字段，默认不启用：

```json
"messages": {
  "keep_latest_duplicates": true,
  "exclude_cmd": true,
  "compact_sequences": true
}
```

处理顺序为：验证原始索引和权威副本 → 排除固定原版 CMD → 在其余消息中对 MessageID 或 `(频道、发送者、非空 ClientMsgNo)` 保留最大原序号 → 按保留顺序从 1 连续编号。发送者或 ClientMsgNo 为空时，遵循原生 v3 不做该幂等检查的行为。

- 普通已读/删除边界映射为“原位置之前（含）仍保留的消息数”。删除旧 seq 1、保留旧 seq 2 时，旧已读位置 1 映射到 0，不能跳到较晚的重复赢家。超过原尾部的旧位置映射到新尾部；0 保持 0。
- CMD 会话及旧同步位置省略。普通权限、会话和消息事件投影仍按原数据合同处理，不因 CMD 排除一并丢弃。
- 原本存在的序号缺口、消息与持久尾部不一致、跨频道同 MessageID、保留候选相互淘汰都拒绝，不用重新编号掩盖源缺失。
- 原 MessageID 索引只有在同频道重复写入且指向最大原序号时才允许；指向较旧行的错误索引仍拒绝。其他源索引校验不变。
- 保留消息的 ID、客户端编号和正文不改；初始化 ID 分配边界仍覆盖被排除记录的最大原 ID。
- 原始消息、索引和元数据保持完整归档。转换与 verify 在不同命名空间中从所选原始记录重建映射，verify 不读取转换侧映射或成功计数来决定正确性。
- prepare 输出带 SHA-256、行数及所选来源摘要的序号映射文件，保留原节点身份、原序号、目标序号、位置边界和删除原因。`wkmigrate export-map --plan ... --workspace ... --archive ...` 可从完整原始归档重新导出，不需挂载原源目录。

客户端缓存和旧游标需要按迁移代次处理，不能把旧数字直接当新数字使用。已询问当前 SDK 及统一缓存/游标重建能力，尚未得到这些信息；映射文件已实现，**客户端实际接入和验收未完成**。
