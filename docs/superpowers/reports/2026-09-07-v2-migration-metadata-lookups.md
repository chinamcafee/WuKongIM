本次完成原版读取规则验证、真实三节点元数据检查，以及可显式启用的设备冷启动选择规则。**尚未完成真实源库 prepare，也未导入或切换 v3。** 原版 v2 没有启动、升级或修改；原生 v3 存储、消息复制与恢复代码仍与既有对照版本一致。

## 设备：规则已实现，现场是否采用仍待选择

原版 `pkg/wkdb/device.go` 的 `getDeviceId` 按 UID 二级索引升序查找，返回第一个 DeviceFlag 匹配的物理 ID。`GetDevice` 缓存未命中时使用该结果；因此冷启动选择最小有效设备 ID，而不是最新时间戳或最大 ID。ID 0 是未找到标记，MaxUint64 被原迭代器上界排除。

`AddDevice`、`UpdateDevice` 可以将另一条记录放进 `(uid, flag)` 缓存；默认缓存 TTL 是 10 分钟。因此，即便同一磁盘状态，热缓存和冷启动也可能接受不同 Token、赋予不同 DeviceLevel。用户已停机的源目录无法还原原进程缓存。

原版代码合成测试已验证：先写 ID 10 和 20 后，热缓存读到 20；清空缓存后读到 10 的原 Token 和级别。测试只使用临时合成数据库，没有用原服务打开现场备份。

现场结果：

| 项目 | 结果 |
| --- | ---: |
| 不同 `(UID, DeviceFlag)` 重复组 | 37 |
| 每个节点额外物理设备行 | 45 |
| 组内 Token 不一致 | 11 组 |
| 组内 DeviceLevel 不一致 | 1 组，包含在上述 11 组中 |
| 最小 ID 对应原记录在所属 Slot 正式副本上不一致 | 0 |
| 重复组所需 UID 索引缺失 | 0 |

原有全量 diagnose 中，Device 只有重复组/成员问题，没有 Device 索引缺失或孤儿索引报告。新检查又确认了这批候选的索引存在和冷启动选中行一致；它不能还原停机前的缓存。

新增计划选项：

```json
{"metadata": {"device_lookup": "v2_cold_start"}}
```

默认不启用，继续拒绝重复凭据。启用后先验证完整原始业务索引，再用磁盘排序选择最小 ID 的**完整原记录**。不混合不同记录的 Token、级别或时间戳，不接受多个 Token。所选记录仍须在正式副本间一致。全部原始记录留在归档；`selection.metadata` 绑定物理组数、被遮蔽行数及全候选摘要。归档重建从原始行/索引重新选择，原生目标离线校验检查实际凭据。

此选项只提供原版冷启动登录语义，消息“保留最新”策略不会自动启用它。现场计划未加入该选项；已询问运营方选择冷启动规则还是由业务后台校准有效凭据，尚未收到本项选择。

## 会话：已读与删除位置一致，物理行和版本仍需区分

原版读取路径并不相同：

- `GetConversation`、更新已读位置及更新删除位置跟随频道唯一索引。
- `GetConversationsByType` 按物理 ID 扫描后覆盖同频道记录，实际保留最大 ID。
- `GetLastConversations` 按 UpdatedAt 排序；`syncUserConversation` 再按频道保留第一条，且旧 API 将 UpdatedAt 作为会话 version 返回。排序前还存在原列表上限，不能仅按每组最大 ID 重建列表。
- 原版删除整条会话时扫描并删除全部重复主记录；不能把其他重复行当成“已删除会话的备份”重新激活。

合成测试已验证唯一索引和最近列表可以读到不同 ID/已读位置，删除位置更新只落到索引选中行，而整会话删除清掉全部重复主记录。

现场发现 **76 个不同逻辑会话重复组**，三个节点分别包含 62、56、59 个物理重复组；这些数字不能相加作为业务会话数。完整检查包含其他节点上的单条对应记录，避免只比较同样重复的副本。

- 76 组在正式副本上由唯一索引读出的 Type、ReadToMsgSeq、DeletedAtMsgSeq、UnreadCount 全部一致。
- 38 组的选中行所有原字段相同。
- 32 组仅物理 ID、CreatedAt 不同；5 组还存在 UpdatedAt 不同；另 1 组只有 UpdatedAt 不同。
- 每组**当前所属 Slot Leader**的单条查询和最近列表候选得到一致的已读、删除位置。
- 一组在非 Leader 节点 1003 上存在更新时间并列、已读分别为 1 和 2。该组属 Slot 36，当前 Leader 为 1001；1001 的单条及最近列表读取一致为 2。工具仍保留该异常证据，没有通过最大已读或多数票消除它。

这些证据证明会话边界问题比原重复计数更窄，但不等于可直接删行。当前实现仍严格拒绝重复会话。后续转换需分别证明唯一索引状态、当前 Leader 列表版本和列表上限的等价关系，再映射已经批准的消息压紧序号；不能直接忽略时间戳差异。此处尚未开发或启用会话合并规则。

## 空身份：真实空频道与独立计数已分开

三个节点各有一对真实空身份记录：ChannelInfo 和 ChannelClusterConfig，均为 ChannelId 空、ChannelType 0，原 hash 为 `562960981632208760`。本次按原身份/所有者关联的主记录检查未发现该 hash 的消息、成员权限、会话或消息事件引用，仅两张配置/信息表相互对应。ChannelInfo 的权限开关均为 0；时间戳及集群配置不是全零记录。

另外两条没有频道身份列的 ChannelInfo 实际只包含 DenylistCount，适用先前已经证明的独立派生计数规则。其中一条仍对应实际黑名单成员，必须保留该权限；不得扩大“空身份归档”范围覆盖它。

本次未把真实空身份记录自动改成管理归档。上一轮已记录 Slot 0 中关联的 9 条物理配置命令；仍需把命令来源、全部引用范围和排除证明接入 prepare/归档重建后，才能去除这项门槛。仅“本次没查到业务引用”不作为完成凭据。
