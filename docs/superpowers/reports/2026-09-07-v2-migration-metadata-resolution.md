# v2 元数据转换与真实源库预检

日期：2026-09-07。固定源版本 `a888f89533d0e7d1b2030e06504ca97f1ad891d4`。

本轮已按用户确认采用设备冷启动凭据规则，并实现重复会话转换及空频道管理记录证明。**真实数据尚未导入或切换到 v3。** 下述本机用例通过不能替代真实源库预检、目标启动及 API/SDK 验收。

## 已实现的规则

- 设备沿用原 v2 冷启动 UID 索引查找：最小有效物理 ID 的完整 Token / DeviceLevel 记录。设备的消息“保留最新”规则不混用；全部源记录保留归档。
- 普通会话按原唯一索引确定已读、删除、未读和类型，全部正式 Slot 副本必须一致；当前 Slot Leader 按原 UpdatedAt 排序的列表选择原版本。时间缺失与存在分别处理，同时间对应不同业务状态或列表与精确读取冲突会拒绝。CMD 的原类型读取按物理 ID 覆盖，批准排除后不导入 CMD 会话。
- 原列表先限数量再去重，检查必须使用原 `conversation.userMaxCount`。计数包括去重前普通会话物理行和停机缓存中确需恢复的新普通会话，超限拒绝。保留的已读、删除位置使用已经批准的消息压紧映射，并独立检查目标结果。
- 只有 ChannelId 空、ChannelType 0 的 ChannelInfo / ChannelClusterConfig 管理记录对可启用归档证明。无业务标志或成员计数、无已支持结构的业务引用、正式副本与保留命令一致，且最后已应用原命令与当前完整配置吻合，才允许归档。缺失、损坏、迁移状态和无法解释的旧引用均阻止完成。权限索引即使主记录不存在，也算业务引用。
- 原始行、原始命令及完整捕获摘要保持不变；归档重建重新执行证明与选择，不接受外部诊断报告代替证据。实际黑名单及其他业务记录继续迁移，业务插件和协议缺口仍阻止完成。

配置见 [操作手册](../runbooks/v2-to-v3-migration.md) 的“原元数据读取规则”。先前 [元数据读取报告](2026-09-07-v2-migration-metadata-lookups.md) 中的“设备待选择、会话待开发、空频道待证明”是上一轮状态，本轮已推进这些事项。

迁移 usecase 7.706 秒、v2 适配 97.464 秒、v3 适配 11.471 秒。新增用例覆盖：

- 1→1、3→1、3→3 集群的会话选择、源目录卸载后归档重建、原生目标导入和离线校验。
- 最近列表版本与精确已读/删除状态分别保留；只在 follower 上出现的列表歧义不替代当前 Leader 读取；正式副本的精确状态冲突仍失败。
- 缺失和错误唯一索引、Leader 同时间冲突、普通列表及待恢复会话数量超限均失败。
- 会话选择与重复消息去重、CMD 排除、消息序号压紧组合，目标已读/删除位置独立校验；损坏目标位置仍能检测。

完整测试后另增加空频道归档与个人黑名单共存的 CLI 组合用例，prepare/export/import/verify 及源路径卸载重建通过（1.620 秒），同时保留两条派生计数和真实黑名单。

固定原版 v2 代码上的临时合成测试也通过：验证热设备缓存与冷启动查找差异、会话精确/类型/最近读取差异、删除位置跟随原唯一索引，以及“limit=2 得到 a,a，然后 API 去重”确实会隐藏另一个频道。测试只打开临时合成库，没有启动或改写现场 v2。
