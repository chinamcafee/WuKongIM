# Issues #927, #928, and #929: recovery verification

Date: 2026-09-08. This document records the diagnosis and staged verification.
Final exact-head SDK/CI receipts are maintained in PR #930; the earlier short
runs below are not a release or a 60-minute SDK acceptance result.

## Changes and evidence

- **#927:** The released C#/JS three-node fixture reproduced a second-fault
  migration timeout. Offline copies confirmed an acknowledged message at offset
  6 on nodes 2 and 3 while node 1 ended at 5; node 2 was unavailable. Waiting for
  a pre-existing second copy prevented recovery, while truncation would lose an
  acknowledged message. Recovery now proves that every responding tail in a
  read quorum belongs to one chain, copies bounded immutable proposal pages
  without truncation, and performs a fresh quorum proof and authority barrier
  before readiness. Divergent/unstable evidence stays unavailable. The new tests
  fail on the earlier implementation and cover both possible surviving leaders,
  an empty survivor, divergent tails, and recovery over multiple bounded pages.
- **#927:** A waiting migration at the front of the task list also starved later
  tasks. The executor now attempts each task in a bounded page; active-index
  cursors rotate across owned hash slots and resume past waiting tasks.
- **#928:** The mock's RECVACK notification precedes the client's accounting
  update. The assertion now waits for the matching client's accounting
  publication. The old test reproduced the zero-count assertion under race;
  the fixed test passed 10,000 repetitions at each of CPU counts 1, 4, and 8.
- **#929:** A new UID authority no longer treats its empty, unproven directory as
  offline. Requested UIDs are reconstructed through bounded active-session
  owner queries, fenced by Slot authority and owner boot/session identity.
  Missing/partial evidence remains retryable. Cache eviction requires a new
  proof, and tombstones/newer owner sequences survive reconstruction.

The branch includes the repair work already merged through PR #923 and current
main. SDK implementation sources and published dependencies were not modified.
A later owner-membership test also covers active Controller-only nodes, since
gateway ownership does not imply the data-replica role. Full validation exposed
an unrelated coordinator test that ordered observer startup before concurrent
status reads; its comparison now preserves phase/call constraints while allowing
that scheduling difference. Production coordinator behavior is unchanged.

Harness-only commits pin the server and preserve local diagnostic evidence;
they are recorded separately below.

## Review-driven fanout correction

The Standards review identified head-of-line blocking of proven UID lookups
behind cold recovery lanes. The Spec review identified a higher-priority path:
serially rebuilding many target groups repeated the same unavailable-owner
wait until the five-second delivery-plan budget expired. The integration
regression reproduced this at group 19 after 20 owner reads, and a busy-lane
regression reproduced the proven-UID timeout. Neither finding was dismissed as
runner noise.

Recovery now packs one 512-recipient page across up to 256 exact targets and
queries each owner once. Existing operation 9 keeps its singleton layout;
operation 10 adds bounded version-2 aligned owner snapshots. Failed target
fences remain isolated, complete proof is rechecked before publication, and
proven lookups do not join cold admission. The original high-fanout regression
now completes with one unavailable-owner read.

The C#/JS five-case fixture passed on `363223538`. Its C++ one-hour run was
gracefully canceled during sustained traffic because review required a new
candidate; this interrupted run is not acceptance evidence. Both SDK fixtures
must be rerun against the repaired final head. The corrected hosted CI run
`34226177054` passed all three benchmarks and the three-node correctness smoke.
The separate pre-existing four-node replica-replacement failure is tracked in
GitHub issue #931.

The follow-up review also caught per-group child deadlines escaping the
presence retry family. A deterministic test reproduced `DeadlineExceeded`
under a still-live parent context; child timeout/cancellation now remains
`ErrRouteNotReady`, while actual parent cancellation and stale fences retain
their original meaning. The app test records a separate session identity per
recipient and verifies exactly one matching committed delivery to each of the
512 recipients. The unavailable-owner integration case passed under race in
0.27 seconds, compared with the original five-second failure.

Both review axes have no remaining actionable findings after these corrections.
Focused unit/race tests and the named FLOW check passed. Final SDK runs and
GitHub checks are recorded against the frozen code head in PR #930 instead of
changing that head merely to add the later test receipts.
