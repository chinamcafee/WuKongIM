## 修复范围

先前的防截断保护保住了历史，但原 Leader 不可达、两个存活副本进度不同的时候无法继续写入。本轮恢复路径先证明所有已观察正式副本尾部属于同一条 exact hash chain，再复制原有完整提案补齐落后的正式副本。复制保持原 manifest、消息内容与标识，不提升 committed。随后重新取得多数前缀证明，并完成当前权威 barrier，才允许写入。

最高 LEO 只用于选取待验证的供数副本，不是提交证据。每个非空尾部都必须与该副本对应位置的完整身份一致。页最多覆盖 256 个位置，并受现有字节预算、超时和执行池约束；中断后从目标的实际持久化进度续传。Learner 不贡献票数。

即使所有副本报告都收到，也不再据此丢弃某个未被多数共同观察到的尾部：读探测不是禁止旧请求继续落盘的持久化承诺。本地修复只在精确 frontier CAS 下追加缺失提案或提升已证明的 checkpoint。若探测后本地又前进，或内容发生冲突，恢复返回错误并保留记录。

严格故障后重试还发现另一个原生问题：本地已明确冲突的重复提案，被不可达副本的 Unknown 覆盖，留下永久 pending。现在本地确定冲突立即走既有持久化命令／业务幂等证明，不等缺失副本。返回 Conflict 不表示远端没有写入，也不是成功响应；已接纳远端任务仍拥有其回调。本地结果本身未知时继续保留 pending，不能跳过。

恢复改动不改变持久化格式、RPC 格式、MinISR 或迁移数据。后续任务调度修复仅在 `pkg/db/meta` 增加既有任务索引的分页读取，索引编码和写入语义不变。真正分叉的持久化日志仍阻断，未实现任意分叉自动修复或新的持久化 promise 协议。

## 真实复验追加发现：失效的故障切换证明

首个候选在隔离环境通过，但在迁移集群的 60 秒发送期限内仍未恢复写入；第一次远端脚本还误设了更短的 12 秒单次 HTTP 超时，该中止记录同样保留，没有计入通过证据。各轮独立保护均恢复了暂停节点。

Operations MCP 报告当时物理 Slot 3 已由节点 1 领导、quorum ready、sync matched；频道检查却返回 unavailable。不能把聚合健康查询缺失当成节点健康。goroutine 摘要显示等待 RPC，随后仅在原本就绑定环回接口的节点 2 临时启用调试，取得完整栈：`startChannelMigrationLoop -> MigrationExecutor.RunOnce -> runLeaderTransferFinalTargetCatchUp -> advanceLeaderTransferDrainProof -> DrainChannel(node 3)`。

这是一个故障换主任务，切换证明失效后从 CommitLeaderMeta 回到 FinalTargetCatchUp，却落入正常主动迁移的旧主排空路径。旧主暂停使唯一修复执行循环也无法继续扫描其他频道。修复让该阶段的 Failover 重新经过现有任务／写入隔离校验，再探测存活目标并生成当前证明；始终不要求已判定不可用的源节点提供正常排空证明。

新增回归覆盖 DrainLeader、FinalTargetCatchUp，以及 CommitLeaderMeta 缺失证明退回后再进入 FinalTargetCatchUp；修复前后者稳定失败，修复后只探测目标节点并进入 CommitLeaderMeta。`pkg/cluster/channels` race 通过。该改动没有放宽写入隔离、元数据版本或目标状态检查。

诊断结束已关闭临时 MCP、撤销唯一临时凭据并关闭节点 2 调试；MCP 保持 stopped，保留节点 1 的执行者选择和审计记录。所有源码外的诊断配置都已恢复。

## 真实复验追加发现：等待非必要的第三个读探测

修复给执行器每轮五秒上限，超时不能生成切换证明或推进任务。任务读取在既有 active index 上按频道 ID／类型分页，并轮转本节点拥有的 hash slots；每轮只返回一个候选，避免未处理的页面尾部被跳过。失去 Slot 领导权后丢弃游标。Blocked、租约不可认领或目标暂不可达的首条任务不能永久占住后续任务。元数据本机应用传递取消上下文，遇到应用锁竞争立即返回可重试的 NotReady，失败不能安装权威缓存。

最小探测测试修复前明确失败于“target probe inherited unbounded migration-loop context”；修复后验证超时不推进证明。另有索引删除后游标续读、同频道不同类型、跨 shard／同 shard 公平轮转，以及元数据锁竞争和失败缓存保护测试。HA69 真实复验结果另附，未完成前不能宣称两轮通过。
