# 迁移验收：三节点暂停故障诊断

日期：2026-09-08。候选基于 `435a83d3cc59c51e3a3c032d7f2e8b6eea6c3d27`，在迁移任务工作树开发。

本文以下部署状态和失败结果属于早期诊断时点。后续 HA76 已部署并通过加强后的两轮消息故障复验，当前结果与剩余分页问题见 [后续修复报告](2026-09-08-native-prefix-recovery.md)。

## 结论与部署边界

本轮发现原生 v3 的恢复安全缺口，与 v2 数据格式无关。先补上禁止不确定截断的保护；“一个节点不可用时持续写入”必须继续独立验收，不能以恢复后历史完整替代。候选没有部署到已迁移集群，也不能据此宣布迁移生产可用。

已迁移集群仍使用 SHA-256 `35a60f396a54ebb147bd6b434c73c45e840e9e756df7c5a0bd004bd367859030`，三个节点正常。只读复核确认 v2 的 601 个源文件和原摘要完全一致，原容器保持退出。100 条原群消息和 147 条重编号消息的 ID、序号、ClientMsgNo、发送者、载荷、RedDot 均一致；群当前有 106 条，另一频道有 149 条。两次 `migration-ha-61-*` 超时请求均未在最终历史中出现。

## 复现与因果证据

原集群使用 256 hash slots、10 个物理 Slot、三副本、MinISR=2，每轮最多扫描一页。对精确标识的第三节点暂停，保留 TCP 连接；独立恢复保护在 78.218 秒内恢复节点。原生 Slot 已换主，但转发到旧 Channel Leader 的 RPC 仍等待，且修复扫描反复从第一个 Slot 开始。

随后在服务器 `/root/wukongim/migration-ha-20260908-62-lab` 新建独立三节点原生 v3 实验，不导入任何 v2 数据。使用独立数据、环回端口及测试进程。完整诊断证明：

1. 业务消息序号 1 在节点 3 和节点 1 同步落盘并得到成功响应；节点 2 的异步副本尚未落盘。
2. 随即暂停节点 3。第一次恢复探测的存活进度为 `[1, 0]`，已提交检查点为 `[0, 0]`。
3. 恢复算法把存活节点多数共同拥有的前缀 0 当成可安全恢复位置，把节点 1 的尾部从 1 截断至 0。
4. 下一次恢复才报告 `[0, 0]`。新消息再次返回序号 1；旧消息按 ClientMsgNo 查询为空。

最初截断的日志超出了默认诊断尾部，完整采集后纠正了“两个副本一开始就为零”的判断。存储缓存错误不是本次原因。额外等待或读取历史可能给异步副本追平时间，使复现消失，不能当作修复。

两个成功写入的副本与两个存活副本只保证有交集，不保证存活副本都包含该记录。因此缺失节点的报告不能按空副本处理，也不能仅凭存活副本的共同前缀认定其余尾部从未被确认。

## 本轮改动

- 转发单次等待默认限制为五秒。只有持久化且携带原 ClientMsgNo 的请求可按现有幂等路径重查权威并重试；未带键和非持久化请求不自动重放。调用方取消保持原语义并使精确旧路由失效。
- 修复扫描保存有界的每 Slot 行游标，跨轮次轮转 Slot；任务预算在页中用尽时保留未处理行，失去 Slot 领导权后清除其游标。
- 原生恢复在存在未稳定报告的副本、已观察到的尾部又超过选择前缀时返回证据不足，阻止后续截断和写入；任何已观察到的已提交位置也不能倒退。没有修改数据库格式或投票数量。
- HTTP 故障用例使用 HTTP 就绪检查，避免用无凭据的 WKProto 连接探测阻塞 HTTP 场景；没有关闭客户端认证。
- 将立即暂停后的历史安全与故障期间可写保留为两个独立 E2E 断言。

## 后续边界

防截断是安全保护，不提供新的提交证明。在第三副本尚未追平且原 Leader 不可用时，它可能拒绝写入，直到证据恢复。要完整通过持续写入验收，需要单独解决原生 quorum 恢复的提交证据与权威 fencing，覆盖最快 follower 成功、另一个 follower 延迟、主节点立即失联、旧主恢复、幂等重试和多次换主。不能通过扩大已同步范围、降低 MinISR、等待全部副本才承认本次测试成功，或修改迁移数据来绕过此缺口。

原始诊断、候选摘要和远端恢复记录保存在工作树忽略目录 `tmp/server-rehearsal-20260908/ha-61/`。它们含测试环境信息，不纳入公开报告。100 GiB／4 小时验收仍按用户决定等待独立环境。
