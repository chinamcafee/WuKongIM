## 实现边界

新增 `history.leader_quorum_prefixes` 显式计划选项。默认仍要求全部正式副本
逐条一致；启用后只在消息比较失败时构建对应频道的完整证明，仍选择当前
Leader 的原行。未改变 v3 存储、复制或目标追加语义。元数据比较、旧迁移标记
证明以及后续 CMD／流消息／去重／序号映射规则保持独立。

检查包括：捕获的节点、Slot 配置及已应用进度；重新校验全部原配置命令摘要；
当前配置与最后已应用命令的完整匹配；保留命令中的删除、成员变化、未完成
迁移、任期倒退和同任期换主；所有节点原消息的连续性、字段摘要、任期、尾部、
严格前缀及正式多数。成员外的消息不能被静默纳入或忽略。

原存储 key 编码由 v2 适配器提供，业务判定在迁移 use case 中。
同 Slot 内完整可解析的空／type-zero 管理命令可识别为另一频道；这项识别
没有放宽默认配置解码，也没有授权空频道留档。后者仍要求原有全捕获证明。
任何无法完整解析的同 Slot 命令继续阻断，因为无法确认是否影响目标频道。

证明只保留 O(源节点数) 摘要，逐行扫描及按序号查找，不在内存缓存频道消息。
每次 prepare 或归档重建使用新的私有证明命名空间，不能复用上次诊断结论。
`selection.history_prefixes` 绑定完整证据报告摘要、频道数及通过／未解决数量；
完整源副本仍进入归档，脱离源库后重新推导同一选择摘要。
