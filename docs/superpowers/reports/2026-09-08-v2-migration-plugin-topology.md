# 插件配置分配支持改变节点数

日期：2026-09-08；工作树 `codex/v2-v3-migration`。

原实现强制源、目标节点一一对应，妨碍允许改变节点数的迁移要求。现在
`plugin_nodes` 为每个目标明确指定一个配置来源；源可供多个目标使用，未选为
目标配置来源的原节点仍完整捕获和归档。未知源、重复或遗漏目标继续拒绝。
本次现场已批准的 1001→1、1002→2、1003→3 计划不变。

转换先读取全部原节点配置，再按目标分配，避免扩容重复扫描整个源库。
`plugin_configs` 可以从未直接映射到目标的原节点选择统一配置；映射仍决定
启用状态和原时间戳，不自动合并不同配置，也不把配置来源当作 Slot 权威。
独立校验重新解码源 Plugin 行，读取原生 Store 文件，不读取转换后的配置记录。

验证覆盖：

- 1/3 个来源到 1/2/3 个目标的六种配置组件组合；原配置、启用状态、纳秒时间戳、
  大整数、未映射的统一配置来源、精确重试和错误捕获节点集。
- 1→3、3→1、3→2、3→3 的完整离线流程：原版派生夹具中的描述性插件记录，
  prepare → export → 移走源目录 → 新工作空间重建 → 原生 import → 重复 import
  → 独立配置与业务数据 verify。检查实际原生启用状态与原来源一致。
- 拓扑专项测试通过，8.116 秒。证据位于私有
  `tmp/server-rehearsal-20260908/plugin-topology-40/`。
- 六个迁移包的最终回归通过：usecase 8.175 秒，v2 adapter 129.284 秒，
  v3 adapter 12.544 秒，CLI 0.663 秒；应用组合和命令编译通过。Linux amd64
  命令构建通过，测试日志、输入摘要和二进制校验和已封存。

完整离线流程刻意使用没有活动业务方法或非空配置的描述性记录；活动插件仍由
正式兼容检查阻止。这个测试不能证明任意插件在改变拓扑后仍等价，也不证明
真实源全部准备完成、目标运行正常或性能达标。没有改动 v3 存储或运行逻辑。
