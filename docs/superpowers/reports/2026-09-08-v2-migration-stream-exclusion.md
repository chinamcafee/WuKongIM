# 流消息排除与频道连续序号

2026-09-08。用户明确“流消息暂时不迁移过来，但是最终要保持频道的 message_seq 严格递增”。这取代此前保留 15 条旧流主消息的要求；沿用已确认的序号压缩和读删边界映射。本轮没有修改 v3 存储或复制逻辑，没有连接现场服务器或导入现场目标。

## 可执行规则

计划新增 `messages.exclude_streams=true`，并要求 `compact_sequences=true`；两张旧流表继续由 `exclusions.legacy_stream_storage=true` 控制。策略变更必须使用全新工作空间和归档。

1. 完整验证原始索引、权威来源、连续历史及持久尾部，再转换选出的业务数据。原本已有的缺口不会因排除消息而被修补。
2. 原 Setting 的流标志 `1<<1` 或非空 StreamNo 均识别为流消息，不从正文推断。先排除 CMD 和流消息，再选重复键的最新普通消息；CMD 与流标志重叠时按 CMD 计数，避免重复计算。
3. 保留消息按同频道原序号排序，目标序号连续为 `1…N`。保留 ID、ClientMsgNo、正文和 RedDot 等其他字段。映射逐行记录原节点、源摘要、原序号、目标序号和排除原因 `stream`。
4. 普通会话读删位置映射为原位置之前（含当前位置）仍保留的消息数。全流频道仍保留频道、权限、成员等元数据，消息尾部和读删边界为 0；首次正常发送应分配 1。有保留消息的频道首次正常发送应为 `N+1`。
5. 流消息关联事件投影/游标按原频道与 ClientMsgNo 精确关联后一并排除。这个事件身份若还对应保留消息，拒绝转换以避免误删。其他事件数据仍迁移。不制造流终态或正文，全部原始记录留在归档。

例：原消息序号 `1(流)、2(普通)、3(流)、4(普通)、5(流)`，目标普通消息序号为 `1、2`，首次新消息为 `3`。旧已读位置 3 映射为 1，不能把尚未读到的原消息 4 标为已读。
