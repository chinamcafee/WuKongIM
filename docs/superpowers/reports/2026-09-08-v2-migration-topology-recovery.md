# 原版 v2 普通历史拓扑与恢复验收

本轮使用未修改的 v2 原版服务器生成普通消息测试库，再通过真实迁移 CLI、
v3 进程、HTTP 和 WKProto 验证。来源代码固定为
`a888f89533d0e7d1b2030e06504ca97f1ad891d4`，独立 HTTP 发送请求和 ACK
作为消息 ID、正文和 ClientMsgNo 的核对依据。单节点来源的新测试库有 3 条
普通 RedDot 消息；三节点来源使用已有原版测试库。测试数据均为合成数据。

## 已确认结果

- 新单节点来源生成器仅通过原版 HTTP 写入；构建前后 976 个归档源码文件
  摘要一致。测试库和 HTTP 记录附带来源与 SHA-256 证明。
- 1 → 1、3 → 1 通过完整 prepare/export/import/retry/独立 verify、原凭据
  登录、历史字段比较、追加、幂等重试和完整集群重启。
- 1 → 3、3 → 3 的历史、初始追加及完整重启通过，但停止频道 Leader 后
  追加持续返回 503。提高到原生故障恢复测试使用的扫描频率后，1 → 3
  仍在 180 秒测试窗口内失败。
- 存活节点的 Manager Controller Raft 状态证明已选出新 Leader，任期 3，
  提交/应用索引持续推进；不能用 Dashboard 的首个 Controller 提示值
  判定控制面未选主。
- 原生 v3、无迁移数据的 `TestChannelThreeNodeLeaderFailoverAfterNodeKill`
  在配置 `WK_GATEWAY_TOKEN_AUTH_ON=false` 后也复现故障后持续 503。
  第一次未配置该值的对照仅在无凭据就绪探针处失败，没有执行故障步骤，
  不计作故障恢复复现。
- 原拒绝测试改用未收敛原版三节点测试库；完整拒绝测试包通过（65.403 秒）。
  健康普通历史现已支持，不能继续把其成功 prepare 当作拒绝测试失败。

## RPC 字段问题

3 → 5 的一次完整重启后，远端历史接口返回额外 25 字节空发送者记录，
与原生恢复屏障格式相符。独立 RPC 回归测试确认 `SyncOnce=true` 在编码解码后
变成 false；原生历史分页本来按该标记过滤内部记录。

修复使本分支尚未发布的 Channel RPC v8 同时传递 RedDot 和 SyncOnce，
旧版本无法表达置位标记时明确返回错误。没有修改存储格式、恢复屏障生成
规则或业务过滤规则。相关 RPC 包及置位/清零、降级拒绝测试通过。
端到端复测仍在继续，尚不能将拓扑恢复整体标为通过。

序号验收遵循业务消息严格递增。原生恢复屏障可以占用日志序号，故恢复后
新业务消息要求大于上一条业务消息，不要求无空洞；迁入保留历史仍逐条
按转换映射比较，首次追加仍检查迁入尾部之后的预期序号。

## 后续恢复修复与复测

原生三节点集成回归先证明：正常 quorum 追加的 follower 已有真实持久化消息，
但未加载 reactor 时修复探针返回 channel not found。修复在权威元数据确认本节点
副本资格后，通过原生 reactor 加载，再读取实际证明；诊断探针仍保持只读。
回归从失败转为通过（3.832 秒），非副本、非 active、取消、激活失败和元数据
竞态拒绝测试通过。

随后切换推进到 verify_new_leader，暴露原生初始化对写入封禁的循环依赖。
quorum 安装现在可以在 transfer fence 下完成恢复和内部屏障，业务 Commit 仍
明确拒绝。清除 fence 只推进 FenceVersion，不换 LeaderTerm，因此屏障使用
与 Install 一致的完整 authority 比较。回归覆盖旧 authority 拒绝、业务写入
拒绝、重复安装、冷恢复和清除 fence 后追加。5 个直接相关包测试通过。

更新后的合成矩阵：1→1、1→3、3→1、3→3 通过全部步骤；3→5 在完整重启后的追加处超时（182.28 秒），尚未执行主动停止 Leader，继续诊断，尚未关闭该阻断项。调试构建通过 Go
编译 overlay 加入有界观察，只用于合成 E2E；正式源码没有调试日志。


## 新副本追平与进度证明

五节点有界任务快照定位到 replica_replace 的 final_target_catch_up：目标是
新增非 ISR 副本，原生 quorum 只向 ISR 发送数据，目标一直 target_lagging。
增加原生 Learners 投影后，恢复和 Commit 将已证明的进度交给有界后台复制，
仍复用逐提案 exact manifest，不改变存储格式，也不让 learner 计入 quorum。
最小原生集成回归从 2.535 秒失败转为通过；覆盖目标不可用时安装仍可完成、
目标恢复后追平、写入封禁下复制、ISR 不可用时 learner 不能满足投票、恢复 ISR
后精确重试和后续提交追平。

另一集成回归证明，已加载 follower 的 reactor 进度不会自动反映后续原生
exchange 落盘。修复检查在权威资格核对后读取真实 exact state，并复核元数据
版本；保持普通诊断接口语义。回归从 6.091 秒失败转为 4.171 秒通过。
四个直接相关包测试通过，原生无迁移三节点 Leader 故障对照通过（27.575 秒）。

五节点复测出现新的明确失败：完整重启时节点 3 启动返回 db: not found
（33.63 秒），正在用私有编译 overlay 定位阶段；尚不能声明五节点验收通过。


## 完整修复后的重复验收

逐层有界 overlay 将启动异常收敛到 Slot FSM 快照恢复。原生元数据最小集成
回归确认：另一个 Slot 的条件写返回 not found 时，同批的有效恢复 watermark
收到同一错误。group commit 仅为显式声明可重建的请求提供一次隔离重建，
元数据每次 Build 重置暂存状态；未提交的失败请求部分写入不落盘，不重试
物理提交错误。元数据三项集成回归通过；commit、meta、message、infra/cluster
四个完整单元包通过，追加 coordinator 回归覆盖请求前后顺序、Finalize 唯一性
及物理提交失败不得重试。

故障叠加快照还确认：Leader 停止时，一个未提升副本的 replacement 任务
停在 cutover_fence，阻止正常 failover。扫描器现在调用原有 guarded Abort
清理这个可撤销任务，下一次扫描再按新的元数据选主；已提升/已验证、嵌入
转移、Leader/epoch 变化与任务不存在的情况不撤销，单 tick 修改数量仍有界。
这复用原生 Slot 命令，没有增加存储兼容字段。

Leader 连接不可用的转发路径还曾错误返回 HTTP 500。类型化 adapter 回归
先失败后通过；DialFailed/Stopped/NodeNotFound 归入原有可重试路由错误。

正式构建上的 3→5 完整黑盒测试连续通过三次：49.09、40.45、42.42 秒。
各次包含历史与凭据、完整重启、幂等追加、主动停止 Leader、恢复后继续追加
与全节点精确历史核对。早先失败记录保留，尚待完整最终矩阵与真实 SDK 验收。
