日期：2026-09-09。状态：交付包全量离线校验、隔离三节点运行及重启验收通过。

## 范围与输入

本轮从冻结的三个 v2 源节点，迁移到另一个全新的三节点 v3 集群。
执行的是已经交付的 Linux amd64 二进制，没有重新编译迁移工具或服务端。
目标采用 256 个 Hash Slot、10 个逻辑 Slot、三副本；各节点仍通过正常
集群协议运行。功能验收使用 Docker Desktop 的 Linux amd64 模拟执行，
宿主机为 arm64；本轮耗时不计入 100 GiB／四小时性能验收。

服务器根文件系统检查时已无可用空间，所以本轮使用本机的隔离 Linux
容器。开始前将本机冷备与服务器原目录逐文件比对：601 个文件、
1,704,886,531 字节的相对路径、大小、SHA-256 全部一致。原 v2 保持停机，
服务器现有 v3 三个容器的标识、启动时间和挂载信息另存为保护基线。

## 离线验收

流水线为 `prepare → export → import → retry(import) → verify`。
准备和导出只读挂载源库；导入及独立校验没有源库、插件原文件或生产者
工作目录挂载，也没有网络。校验重新创建独立工作目录。重复导入发生在
任何目标启动之前。每个阶段保存 JSON、标准错误、执行时间、退出码和
容器配置；内存上限 1.5 GiB，宿主磁盘预留 2 GiB，每阶段限时 90 分钟。

首次脚本运行发现，预建的空工作目录会被 `wkmigrate` 以“缺少 identity”
拒绝。已修正为只挂载父目录，由工具创建子工作目录；失败日志保留，
随后使用另一个全新输出目录重新演练。该修正没有涉及迁移工具或 v3
存储逻辑，并有无后台进程的脚本测试覆盖。

### 本机空间处理

为给校验预留空间，完成导出后清理了本轮准备阶段的可重建临时库。
清理前保存了 552 个文件的大小和 SHA-256 清单、工作目录身份以及完整
序号映射；映射现在位于私有输出的 `retired-prepare-work/`。原始归档、
准备报告和后续目标数据继续保留。清理脚本验证计划身份、完成标记、
前序阶段成功以及没有容器挂载该目录，只处理本轮确定的临时路径。

宿主机随后仍有 Docker 虚拟机进程持有已删除文件。一次辅助容器因镜像
默认 UID 10001 无权写内核接口而失败；以 root 运行的单次辅助容器成功
执行 `drop_caches=2`，回收未使用的目录项及 inode 缓存后，宿主余量恢复
到约 6.8 GiB。辅助容器已清理。这是本机测试环境的空间处理，并非迁移
命令要求；缓存状态的变化也进一步排除了本轮性能验收的适用性。
接口行为见 [Linux 内核文档](https://www.kernel.org/doc/html/latest/admin-guide/sysctl/vm.html#drop-caches)。

首次完整校验在 2,803.66 秒时触发磁盘预留保护，记录 `context canceled`，
没有生成成功报告。失败容器已停止并清理，原始日志和执行记录移入
`verify-attempt-01/` 留存。后续检查时宿主空间已恢复；再次校验沿用该独立
校验工作目录、同一计划、归档和交付二进制，重新从归档推导预期值并
完整检查全部目标，不跳过上次已读节点。第二次执行继续保留 2 GiB 预留
和 90 分钟期限。源和导入工作目录仍不挂载。

## 运行及重启验收

启动前已保存三个目标的完整副本 `runtime-stopped-generation/`，255 个文件
的相对路径、大小和 SHA-256 与通过校验的目标逐项一致，保留初始生成状态。

运行检查 100 条普通群历史和 147 条重编号历史的 ID、序号、ClientMsgNo、
发送者、负载和 RedDot；核对恢复会话的已读基线及新增未读。分别通过
三个 API 入口发送新消息，要求序号严格大于当前频道尾部；写入轮次之间
整组重启两次，最后再进行一次只读重启，确认最后一批 ACK 对应的消息也
能恢复。每次重启后检查原历史、新消息和未读。运行容器使用独立内部
网络，最终通过容器内 HTTP 请求访问各节点 API，不发布宿主端口；
完成后仅清理本轮所有的容器和
网络，保留数据和证据。

首次运行检查遇到宿主无法访问 Docker 内部网络发布端口，三个服务端
自身已正常启动，容器内 `/readyz` 返回就绪。改为在同一容器网络内通过
HTTP 检查；请求体经标准输入传递，不放在命令行参数中。服务器配置不变。

随后原脚本错误地将接收者视角的单聊历史频道 ID 用作发送目标，发送到了
发送者自己的频道，触发序号断言。普通群已经正确追加到 101；单聊的
最小诊断显示错误目标不增加原 147 条历史，正确目标追加为 148。修正
脚本发送单聊时使用接收者 UID。没有修改迁移工具、交付二进制或 v3 存储。
每次诊断日志和测试目标保留；最终完整验收重新从保存的初始快照恢复，
255 个文件逐项匹配离线通过的原始清单后才启动。

最终运行返回 `passed`：在三个 API 入口逐轮检查全部 247 条样本的原始
字段、恢复会话和已读基线；每轮每个频道增加一条普通消息，共新增六条。
所有新消息的 ID 均高于源最大 ID，未触发不确定 ACK 重试。

所有节点正常停止，容器没有 OOM；仅本轮拥有的运行容器和内部网络已清理。

Docker 输出的数组顺序变化当成部署改变。本轮对服务器只执行只读检查。

新增脚本默认单元测试覆盖保守单节点集群计划、只读源与归档隔离、独立
校验工作空间、无后台进程的 dry run，以及现有输出、路径穿越、输入重叠、
嵌套目标、可变镜像和错误二进制摘要的拒绝。`go test ./scripts -count=1`
通过，交付前再次运行 `go test ./scripts -run '^TestMigrationRehearsal' -count=1`
通过；以上均设置 `GOWORK=off`。`git diff --check` 通过。

PR 评审随后发现异步 `docker run` 在创建期间取消可能遗漏容器的竞态。
通用脚本已改为先创建并确认容器 ID/归属，再启动工作；清理等待启动客户端
结束后再次检查容器状态。受控 Docker CLI 的进程级回归测试覆盖创建时取消、
延迟启动时取消和正常完成，均要求停止并移除本轮容器。该后续脚本变更不
改变上文实际演练使用的二进制、数据或命令参数；不将受控 CLI 测试当作
再次执行完整数据迁移。
