# v2 → v3 离线迁移工具设计

更新：2026-09-08。工具及组件验收已实现，现场完整源尚未完成预检、导入和切换。
当前剩余范围以[阻断项台账](../reports/2026-09-08-v2-migration-blockers.md)为准；
100 GiB 性能验收已获准待环境提供后执行。

已部署 v2 保持原版，不升级、不替换、不启动停机备份。迁移使用 v3 原生存储与
恢复规则；早期迁移专用 proposal version 2/3 和恢复分支已经撤回。无法等价
表示的业务状态必须阻止完成，不能扩大 v3 存储格式来容纳旧数据。

当前消息合同：显式排除 CMD、全部流消息及旧流分片／元数据，再按频道内原
MessageSeq 对重复 MessageID 或作用域内 ClientMsgNo 保留最新项。保留消息按原
顺序连续编号为 `1…N`，保留原 ID、内容及包括 RedDot 在内的可表达字段；普通
会话读删位置映射为保留前缀数量，新消息由 v3 原生分配 `N+1`，空历史从 1 开始。
旧 CMD 会话和无歧义关联的被排除流事件投影不导入；全部源行仍完整留档。
客户端验收按 docs-site 的固定 SDK 版本展开，先使用 Web 1.3.5 示例；旧缓存和游标必须按迁移代次清理或映射，实际切换验收尚未完成。

元数据使用显式的原版设备冷启动查找、当前 Slot 会话列表和原数量上限规则。
无业务引用的空频道管理记录、用户创建／更新时间可以按已批准范围完整归档；
其余用户字段、凭据、权限和会话业务状态仍严格比较。

消息副本默认逐条一致。显式 `history.leader_quorum_prefixes` 仅允许当前 Leader
与正式多数保存相同完整历史、其余副本为严格前缀且已应用配置日志无歧义的情况。
源码读取、全部字段、任期、尾部和保留命令都参与证明；不选择最长 follower，
不证明历史 ACK。真实 29 个差异频道中 28 个通过该规则；1 个空 Leader／同任期
换主频道的两条普通消息现已获准恢复。`history.recoveries` 显式绑定频道、源捕获、
完整诊断、指定完整副本及消息条数/摘要；重新核验证据，报告保留原异常结论与
恢复决定。只支持当前 Leader 完全无历史且正式多数保存同一完整历史的范围，
删除、内容冲突及未知异常不能凭恢复决定绕过。

活动插件必须提供每个源节点原程序、注册和配置的完整证据。当前仅实现固定
AI 示例 Receive 程序的精确兼容 profile，显式保留节点设置并统一有效配置。
未知程序、方法或未映射业务绑定继续阻断；程序准备检查不代替最终集群运行验收。

空历史 HTTP 行为已同步 main 的 `065317e0b` 修复；全流频道在首次 SEND 前
返回空历史，仍保留成员校验和真实错误。具体实现和验收证据见
[操作手册](../runbooks/v2-to-v3-migration.md)及台账链接的分项报告。

## 已确定的决策树

1. 迁移方式：离线，允许完整停机窗口。
   - 已部署 v2 必须保持原版；不升级、不打补丁、不注入进程、不要求新增接口。
   - 运维通过已有业务/部署设施停止流量，必要时用原有接口记录运行状态，
     再正常停止全部相关节点，收集完整数据和实际配置。
   - 工具直接适配原版停机数据；`prepare` 改为离线预检，不具备冻结在线 v2
     或证明其所有在途任务已排空的能力。
2. 业务数据：完整保留源中实际持久化的业务状态。
   - 源基线为停写后 v2 权威节点实际可读、正常停机后仍可恢复的持久业务状态。
     不为源没有记录的历史 ACK 或外部通知交付结果补造证据。
   - 对保留消息保留 `message_id`、客户端幂等标识和完整消息字段；按已授权策略排除 CMD/流消息和旧重复项，并映射 `message_seq`。
   - 保留用户、设备凭据、频道、成员、权限、普通会话及映射后的读删位置；CMD 会话省略。
   - 保留未被批准排除的消息事件投影、终态、最后事件信息和事件序号。
   - 无法等价表达且影响业务的状态必须明确阻止迁移完成。
3. 目标：全新的空 v3 集群。
   - 支持单节点和多节点来源与目标，允许改变节点数。
   - 目标遵循正常集群语义，使用 256 hash slots。
   - v2 Raft、Controller/集群配置和旧副本分配不直接复制成 v3 状态。
4. 不一致与失败：无法证明完整性、发现冲突/损坏或通知未排空时停止并报告。
   - 不以最大序号、最大更新时间或简单并集选择权威数据。
   - 中断后可以恢复同一次迁移，源身份或目标计划改变时拒绝续跑。
5. v3 无对应功能的旧管理数据：保存在带校验和的完整迁移归档。
   - 包括旧压测机记录、历史运行计数和插件注册描述等。
   - 报告逐项列明归档与业务导入结果，归档不能替代业务兼容。
6. 验收目标：100 GiB 源业务数据，从停写到校验通过且可切换不超过 4 小时。
   - 记录参考机器、磁盘、节点/副本拓扑、源逻辑数据与实际磁盘占用口径。
   - 用户已明确先完成开发和本机功能测试，100 GiB 性能验收待提供环境。
   - 磁盘容量按运行时实测；不得据小规模结果宣称通过 100 GiB 验收。

## 数据合同与转换边界

| 源数据 | 目标处理 | 必须验证的性质 |
| --- | --- | --- |
| 用户和设备 | v3 用户/设备表 | UID、设备标志、Token 和等级准确保留 |
| 频道策略 | v3 Channel 元数据 | 封禁、解散、发送封禁和陌生人权限等业务行为 |
| 订阅者 | v3 subscribers 与相应 UID membership | 成员集合、目录和历史可见范围一致 |
| 黑白名单 | v3 派生权限频道 | 不误创建普通会话，不改变权限结果 |
| 系统 UID | v3 内部系统账号集合 | 各节点启动后的系统账号判定一致 |
| 插件用户绑定和有效配置 | v3 绑定与节点配置 | 活跃插件兼容性需通过，未适配不能视为成功 |
| 普通会话 | membership、读删/激活状态 | 不把隐藏会话误转换为退出成员的 tombstone |
| CMD 会话 | 按显式策略只归档 | 不遗留指向已排除 CMD 历史的同步位置 |
| 消息 | v3 typed message storage | ID/seq、payload、全部协议字段、索引和幂等性 |
| 消息保留边界 | v3 原生日志与提交边界 | 先验证原始完整范围，再将保留消息连续编号并映射游标 |
| 消息事件 | 精确状态和 cursor 导入 | 不通过重新 replay 生成不同的事件序号 |
| 停机会话文件 | 按 v2 恢复语义合并到逻辑结果 | 不遗漏未落库尾部，不覆盖更权威的新状态 |
| Webhook/消息通知积压 | 运维停机前处理；工具检查可读取的持久积压 | 不自动重放；不能将无磁盘积压解释为所有外部通知已成功交付 |
| 无对应功能的旧管理记录 | 可校验归档 | 内容完整，报告明确标识其不在 v3 运行时启用 |

v2 的普通未读数通常由消息尾部、读位置与用户最后发送消息派生，不能仅根据
旧表存在 `UnreadCount` 字段就重写 v3 未读模型。源中遗留独立未读数可能影响少量
响应边缘，预检必须识别并与实际公开 API 行为交叉核对；不能静默改写原读位置。

源版本本身仅保存每个 event key 的最新投影及消息级事件序号，未保存完整逐条
事件历史。迁移不承诺恢复源中已经不存在的数据。

## 操作流程

独立的 `wkmigrate` CLI 保留 `wkdb` 的节点本地边界。实际参数、准备条件和
切流步骤见[操作手册](../runbooks/v2-to-v3-migration.md)。

1. 运维停止业务流量，按原版 v2 现有能力处理待完成工作；正常停止全部 v2
   节点，收集完整数据目录与实际配置。工具只读访问这些源目录或其停机副本。
2. `prepare`：离线检查源版本/格式、节点清单、配置、各类存储与尾部文件，
   验证可确定的数据范围与副本一致性，报告冲突、损坏、持久积压和证据缺口，
   生成绑定不可变源清单的预检结果。无法解决的业务完整性问题阻止继续。
3. `export`：验证停机源与预检结果一致，读取并合并确定的数据，生成版本化、
   分块、带计数和校验和的逻辑迁移归档。
4. `import`：根据显式目标节点配置和副本计划初始化空目标的存储，写入业务数据，
   建立 v3 自身的归属、复制及消息提交状态。支持同一次迁移中断恢复。
5. `verify`：首次启动前独立读取源逻辑结果与目标，逐域比较计数、标识、序号范围、
   字段、消息摘要链、索引及原生初始化快照。成功状态为 `offline_verified`。
6. 运维隔离启动目标集群，另行验收公开 API/SDK、配置和外部集成；通过后恢复业务
   流量。工具报告始终保留 `cutover_ready: false`，不会自动授权切流。

命令不将路径存在视为可用源，不将单个节点目录视为完整集群，也不将一次
`Append` 成功视为消息在多副本目标已经可读。

## 实现边界

- `cmd/wkmigrate` 是 CLI 入口；参数与输出适配放在窄的 access 包。
- 迁移编排放在 `internal/usecase` 的迁移域，通过窄接口连接源读取、归档、
  目标安装和验证能力；只在 `internal/app` 下组合具体实现。
- v2 格式读取在专用 infra 适配器内，固定来源版本并使用只读打开；不恢复
  `internal/legacy` 或 `pkg/legacy`，不将旧服务端运行时复制进 v3。
- 不交付或依赖修改版 v2；新增代码放在迁移工具和 v3 目标侧。原版 v2 的存储
  解码、恢复语义和现有接口就是源适配器的能力边界。
- 复用 `pkg/db/transfer` 及原生 typed storage／备份接口，映射可表达的业务字段
  和精确事件状态；不增加迁移专用 schema、proposal 版本或运行恢复分支。
- 集群布局与初始化复用 v3 的 Controller、Slot 和 Channel 正常规则。
  单节点集群执行相同的集群模型。
- 导入阶段隔离业务流量和历史副作用；目标首次新消息从映射后的尾部之后写入。

## 完整性、资源与恢复

- 读取源实际 shard/slot 配置。v2 默认 64 slots、8 个数据库 shards；两者不同，
  不可直接视为目标 256 hash slots 的布局。
- 元数据按 Slot 权威选择，消息按 Channel 副本组权威选择；保留删除语义。
- 能访问原版运行集群时，停机前通过已有接口记录稳定的权威、配置和进度，
  并与最终停机数据核对。只有停机目录时，必须能从源配置、日志和副本内容
  确定一致来源；不能确定则明确报告，不能把任意一个节点当权威。
- 预检记录绑定节点、配置、版本及可确定的数据范围；停机目录绑定不可变文件
  清单与摘要。副本最大序号不能证明历史提交，不将原版源未保存的证据伪造成
  工具保证。对可迁移源状态的判定须以源码、正常恢复语义及交叉测试明确。
- 归档按有界块写入，逐块校验；全局排序、去重使用分区/外部排序，避免所有
  用户、频道、消息、十万成员群一次性装入内存。
- 批次同时限制行数和字节数；并发、队列、打开文件数和峰值内存有界。
  评估 CPU、分配、磁盘放大、校验开销及目标副本数带来的额外写入。
- 完成块与进度只在持久化成功后发布；重跑校验已完成块，源变化或计划变化拒绝
  续跑。同一目标不得混入其他迁移或业务写入。
- 保留源和失败现场；部分目标不会被标记为可切换。禁止默认删除已有目标。
- 切换前可继续使用原 v2 数据回退；v3 已接受新业务写入后的反向增量迁移不在
  本工具范围内，报告须明确这个边界。

## 验证计划

已确认的测试边界：原版 v2 生成数据的只读源适配器、公开 typed storage 接口、
`prepare/export/import/verify` CLI，以及真实集群的公开 API/SDK。单元测试和集成
测试在这些边界验证行为；不依赖转换器内部函数或自行生成的预期值证明正确。

1. 固定版本真实 v2 数据生成/解码交叉验证，覆盖每类业务数据与停机尾部文件。
2. 快速单元测试覆盖格式校验、映射、摘要、冲突、损坏、序号边界及恢复状态。
3. 进程和真实时间相关测试使用 integration 或 E2E build tags，遵守目录规则。
4. 黑盒功能矩阵至少包含 1→1、1→3、3→1、3→3，以及一个目标节点数变化的
   多节点组合；验证目标重启和 Leader 切换后仍可读写。
5. 覆盖非 1 起始或不完整历史的拒绝边界，以及大 ID、原始二进制 payload、特殊
   频道键、权限名单、删除／隐藏会话和消息事件。按批准策略验证 CMD／流消息
   排除、连续序号、迁后首条新消息及幂等重试，不能把无法证明的源缺口自动补齐。
6. 使用未经修改的精确 v2 生成测试源。注入中断与重试、缺源节点、预检记录
   不匹配、坏记录、重复/冲突副本、非空目标、遗留通知和目标中途写入，检查
   失败明确且不误报成功。
7. 全量数据摘要与公开 API/SDK 结果分别验证，不能只用同一套转换代码自证。
8. 本机只运行容量允许的功能和小规模资源测试；100 GiB/4 小时验收在用户提供
   环境后执行并单独出具报告。该性能结果目前未验证。

## 原版 v2 的能力边界

- v2 Slot replica API 已提供 leader、term、配置版本及 log/applied/committed
  信息；聚合 API 会跳过离线副本，必须另外对照完整配置集合检查。
- v2 Channel replica API 没有提交边界。仅新增 committed getter 也不充分：
  冷频道重建会把最后落盘 seq 当 applied，并用于初始化 committed。
- 已取消依赖新增冻结、提交证明、排空接口的设计。离线预检不能签发在线冻结
  或历史多数派提交证明；也不能据此笼统断言原版现有数据无法迁移。
- v2 没有 Webhook 完整排空 API，磁盘队列深度不能覆盖缓存、重试和发送中任务。
  正常 Stop 也不等待这些任务全部成功；仍不能把重试耗尽丢弃或无法观测的状态
  当作成功交付。
- 已核实 v2 公开 `syncMessages` 定位 Channel Leader 后直接读取 wkdb，未按
  committed 截断（`internal/api/message.go:1198`）。`LoadLastMsgs` 使用落盘
  最后序号（`pkg/wkdb/message.go:412`）。因此保留停写后权威节点的持久历史
  符合源当前读取语义，不需要为每条历史补造多数派提交证明；其他副本独有的
  尾部不得直接并入，冲突必须报告。
- Slot 日志保留 Index/Term/Data 与持久 applied 信息，可与停机前现有 API 的
  leader/term/config/progress 核对。相同 applied 不等于逻辑业务行相同，仍需
  按 Slot 校验逻辑数据，并识别删除、日志分叉、缺失与投影冲突。
- 停机后的 diskqueue 元数据与残留记录可以只读解析并保存，但消费到内存就
  推进磁盘读位置，早于 HTTP 成功。交付不明状态要结合原有日志或接收端记录
  单独报告；不能将“可迁移持久业务数据”描述为“所有外部通知恰好交付一次”。
- 验证基线必须使用未经修改的固定 v2：比较停写后其公开读取结果、正常停机
  后的源解析结果以及目标 v3 行为，覆盖副本冲突和通知不确定状态。
